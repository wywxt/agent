## 一、存储架构

```
~/.mewcode/memory/          ← 用户级（跨项目共享，类型：user / feedback）
    ├── MEMORY.md            ← 索引文件（一行一个记忆指针）
    ├── my-role.md           ← 单个记忆文件（YAML frontmatter + Markdown）
    └── code-style.md

{project}/.mewcode/memory/  ← 项目级（跟随项目，类型：project / reference）
    ├── MEMORY.md
    ├── api-arch.md
    └── database-schema.md
```

### 记忆文件格式

```markdown
---
name: my-role
description: I am a backend developer specializing in Java
metadata:
  type: user
---

I work primarily with Spring Boot and PostgreSQL.
I prefer clean architecture with separation of concerns.
```

### 索引文件格式（MEMORY.md）

```markdown
- [my-role](my-role.md) — I am a backend developer specializing in Java
- [api-arch](api-arch.md) — The API uses REST with JWT authentication
```

## 二、记忆提取（MemoryManager.extract）

### 触发条件

每 `EXTRACTION_INTERVAL = 1` 轮对话触发一次（即每轮都检查，`shouldExtract()` 每 N 轮返回 true）。

### 提取流程

```java
public void extract(LlmClient client, ConversationManager conv) {
    // 1. 取最近 40 条消息
    // 2. 扫描已有记忆，生成 manifest（供 LLM 做去重）
    // 3. 构建提取 prompt
    // 4. 调用 LLM 流式提取
    // 5. 解析输出（MEMORY_NAME/TYPE/DESC/BODY 格式）
    // 6. 写文件 + 更新 MEMORY.md
}
```

### 提取 Prompt 关键内容

```
输出格式：
  MEMORY_NAME: <kebab-case-name>
  MEMORY_TYPE: <user|feedback|project|reference>
  MEMORY_DESC: <one-line description>
  MEMORY_BODY: <content>
  ---

类型说明：
  user/feedback → 保存到 ~/.mewcode/memory/
  project/reference → 保存到 .mewcode/memory/

不保存的内容：
  - 可从代码中推导的模式
  - Git 历史、调试方案
  - 临时任务细节
```

### 去重检查

提取前扫描已有记忆生成 manifest，告诉 LLM：
```
## Existing memory files
- [user] my-role.md: I am a backend developer...
- [project] api-arch.md: The API uses REST...

Check this list before creating — update an existing file rather than creating a duplicate.
```

## 三、记忆注入（injectMemories）

```java
public void injectMemories(ConversationManager conv) {
    String reminder = buildSystemReminder();  // 构建 autoMemory 系统提醒
    if (conv.getMessages().isEmpty()) {
        conv.addUserMessage(reminder);
        conv.addAssistantMessage("Understood, I'll keep this context in mind.");
```

## 四、MemoryConsolidator（记忆整理 = "Dream"）

### 触发条件

三个条件全部满足时触发：

```java
public void maybeRun(LlmClient client, ConversationManager conversation, String protocol) {
    // 门 1: 时间门（距上次整理 ≥ 24h）
    double hoursSince = (now - lastConsolidatedAt) / 3600000.0;
    if (hoursSince < 24) return;

    // 门 2: 扫描节流（10 分钟内不重复扫描）
    if (now - lastScanAt < 10 * 60 * 1000) return;

    // 门 3: 会话门（至少 5 个新 session）
    if (sessionIds.size() < 5) return;

    // 门 4: 获取文件锁（防止并发整理）
    Long priorMtime = tryAcquireLock();
    if (priorMtime == null) return;

    // 在后台虚拟线程中执行
    Thread.startVirtualThread(() -> run(client, conversation, protocol, sessionIds));
}
```

### 锁机制

```java
private Long tryAcquireLock() {
    Path path = memDir.resolve(".consolidate-lock");
    // 读锁文件获取上次 mtime + holder PID
    // 如果锁持有者进程仍在运行 + 锁未过期(< 1h) → 获取失败
    // 否则写入当前 PID → 回读验证 → 获取成功
}
```

### 整理流程（四阶段）

```
Phase 1 - Orient（定向）
  - ls 记忆目录
  - 读 MEMORY.md
  - 浏览已有文件

Phase 2 - Gather（收集信号）
  - grep 新 session transcripts（不全部读取）
  - 寻找与已有记忆矛盾的事实
  - 寻找值得持久化的新发现

Phase 3 - Consolidate（整理）
  - 合并新发现到已有文件（避免重复）
  - 将相对日期转为绝对日期
  - 删除已被证伪的记忆

Phase 4 - Prune（修剪）
  - 更新 MEMORY.md（≤ 200 行，≤ 25KB）
  - 删除过时条目
  - 缩短过长描述行
```

执行方式：创建一个独立子 Agent（PermissionMode.BYPASS），只带 ReadFile/WriteFile/EditFile/Glob/Grep/Bash 工具。
