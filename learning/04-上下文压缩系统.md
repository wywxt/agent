## 设计理念：双层压缩

```
Layer 1: ToolResultBudget (纯本地 I/O)
  触发：无条件执行（每轮循环前）
  操作：超大 tool_result → 溢写磁盘 → 摘要占位符替换
  成本：几乎为零（只做字符串比较 + 文件写入）
  
Layer 2: ContextCompactor (LLM 驱动的摘要)
  触发：estimated tokens ≥ 窗口阈值时
  操作：旧消息 → LLM 生成结构化摘要 → 重建对话
  成本：一次完整的 LLM 调用
```

两个层次各司其职——Layer 1 减少 Layer 2 的输入量，Layer 2 处理 Layer 1 无法处理的语义压缩。

## Layer 1: ToolResultBudget

### 裁剪规则

```
规则 1：单个 tool_result > 50,000 字符
  → 内容溢写为 disk file → 替换为 <persisted-output> 预览摘要
    摘要包含：文件路径 + 大小 + 前 2KB 预览

规则 2：单条消息所有 tool_results 合计 > 200,000 字符
  → 按大小降序，从最大的开始溢写，直到 total ≤ 200K
```

### ContentReplacementState：冻结机制

这是 Prompt Cache 得以命中的关键：

```java
public final class ContentReplacementState {
    private final Set<String> seenIds;       // 所有见过的 tool_use_id
    private final Map<String, String> replacements;  // id → 替换后的摘要字符串
}
```

**不变式：`keys(replacements) ⊆ seenIds`**

工作流程：

```
第 1 轮：
  tool_use_id = "abc", 结果 120KB → 溢写为 <persisted-output> 摘要
  → seenIds.add("abc")
  → replacements.put("abc", "摘要字符串 v1")

第 2 轮（对话被重新发送给 LLM）：
  tool_use_id = "abc" 仍在对话中
  → replacements.get("abc") = "摘要字符串 v1"  ← 使用完全相同的字符串
  → 不重新读取文件，不重新生成摘要
  → 前缀 byte-identical → Anthropic Prompt Cache 命中！
```

### 特殊处理：Spill Readback

```java
// 如果 agent 尝试用 ReadFile 读取溢写文件 → 跳过裁剪
```

## Layer 2: ContextCompactor

### 压缩阈值计算

```java
// 保留 SUMMARY_OUTPUT_RESERVE (20K) 给摘要响应
int effectiveWindow = contextWindow - min(maxOutput, 20_000);

// 软触发线：留有 13K 安全边距
int softThreshold = effectiveWindow - 13_000;

// 硬触发线：留有 3K 安全边距（强制压缩）
int hardThreshold = effectiveWindow - 3_000;
```

### 核心算法：computeKeepStartIndex()

```java
static int computeKeepStartIndex(List<Message> messages) {
    int n = messages.size();
    int accumulated = 0;
    int kept = 0;
    int keepStart = n;  // 从末尾向前走

    for (int i = n - 1; i >= 0; i--) {
        int msgTokens = estimateTokens(List.of(messages.get(i)));

        // 上限保护：单条消息不能超过 40K
        if (accumulated + msgTokens > 40_000 && kept > 0) break;

        accumulated += msgTokens;
        kept++;
        keepStart = i;

        // 满足任一条件即停止：累积 ≥ 10K tokens 或 保留 ≥ 5 条消息
        if (accumulated >= 10_000 || kept >= 5) break;
    }

    // ★ Pairing 保护：保证 tool_use↔tool_result 不拆散
    while (keepStart > 0 && isToolResultMessage(messages.get(keepStart))) {
        keepStart--;  // 往前多保留一条（assistant tool_use 消息）
    }

    return keepStart;
}
```

### 摘要 Prompt 设计（384 行）

要求 LLM 生成涵盖 9 个方面的结构化摘要：
1. Primary Request and Intent（用户意图）
2. Key Technical Concepts（技术概念）
3. Files and Code Sections（文件+代码片段）
4. Errors and Fixes（错误及修复）
5. Problem Solving（解决的问题）
6. All User Messages（所有用户消息）
7. Pending Tasks（待处理任务）
8. Current Work（当前工作状态）
9. Optional Next Step（建议下一步）

输出格式：`<analysis>` 思维过程 + `<summary>` 结构化摘要。

### PTL 重试机制（Prompt Too Long）

摘要请求本身可能超出上下文窗口 → 自动丢弃最老的消息组重试：

```java
private static String requestSummaryWithPTLRetry(...) {
    for (int attempt = 0; ; attempt++) {
        try {
            String raw = requestSummary(client, prompt, toolSchemas);
            return formatCompactSummary(raw);
        } catch (RuntimeException e) {
            if (!isPTL || attempt >= 3) throw e;  // 最多 3 次

            // 按 API 轮次丢弃最老的一组消息
            int tokenGap = estimateTokens(currentPrefix) / 5;
            List<Message> truncated = truncateHeadForPTL(currentPrefix, tokenGap);
            if (truncated == null) throw e;
            currentPrefix = truncated;  // 用缩短后的前缀重试
        }
    }
}
```

### Recovery Attachment（压缩后恢复）

压缩后在 user summary 消息末尾附加：

```
## Recently read files          ← 最多 5 个文件，各 ≤ 5K tokens
## Active skills                 ← 曾加载的 Skill SOP，总预算 25K tokens
## Available tools               ← 当前会话可用的工具列表
## Note                          ← 提醒 Agent 重新读取源码，不要猜
```

### Circuit Breaker

```java
public static class AutoCompactTrackingState {
    private int consecutiveFailures;

    public boolean isTripped() {
        return consecutiveFailures >= 3;  // 连续 3 次失败 → 跳闸
    }

    public void recordFailure() { consecutiveFailures++; }
    public void reset() { consecutiveFailures = 0; }
}
```

### UsageAnchor 锚定机制

```java
public record UsageAnchor(int baselineTokens, int anchorCount) {}

// Token 估算：
public static int currentTokens(List<Message> messages, UsageAnchor anchor) {
    if (anchor == null) return estimateTokens(messages);  // 冷启动回退

    // anchored 模式：baseline + 仅估算新增消息
    List<Message> appended = messages.subList(anchor.anchorCount(), messages.size());
    return anchor.baselineTokens() + estimateTokens(appended);
}
```

### compact_boundary 持久化

压缩完成后在 session JSONL 文件中追加一条 `compact_boundary` 记录：

```json
{"role": "system", "type": "compact_boundary", "content": "{\"summary\":\"...\",\"keep\":[{\"role\":\"user\",\"content\":\"...\"}]}", "ts": 1234567890}
```

这样 `/resume` 恢复时只重建 compressed state（摘要 + 保留尾部），不重放原始完整对话。

## 压缩流程图

```
每轮 Agent 循环开始
    │
    ├─ Layer 1 (无条件执行)
    │   ToolResultBudget.apply()
    │   → 溢写超大 tool_result → 摘要占位
    │
    ├─ Token 估算
    │   currentTokens(messages, usageAnchor)
    │
    ├─ tokens < softThreshold? → 跳过 Layer 2
    │
    ├─ tokens ≥ hardThreshold? → 强制压缩 (forceCompact)
    │
    └─ softThreshold ≤ tokens < hardThreshold?
        → 尝试 autoCompact()
        → 成功: reset circuit breaker
        → 失败: recordFailure(), 如果累计 3 次则 skip
```
