## 一、权限模式（PermissionMode）

```java
public enum PermissionMode {
    DEFAULT,   // 默认：FILE 自动允许，COMMAND 询问
    BYPASS,    // 绕过模式：全部放行（用于子 Agent / 后台任务）
    PLAN,      // 计划模式：只允许只读 + Agent/AskUser/ExitPlanMode
    ACCEPT,    // 接受模式：全部自动允许
}
```

## 二、6 层决策链

`PermissionChecker.check()` 返回 `CheckResult` (ALLOW / DENY / ASK)：

```
                    ┌─────────────┐
                    │ 工具调用请求  │
                    └──────┬──────┘
                           ↓
 Layer 0: Plan 模式例外
   PLAN_MODE_ALLOWED_TOOLS = {Agent, ToolSearch, AskUserQuestion, ExitPlanMode}
   在 Plan 模式 + plan file 存在时直接放行
   WriteFile/EditFile 只允许写入 .mewcode/plans/ 路径
                           ↓
 Layer 1: 安全命令白名单
   SAFE_COMMANDS 包含 80+ 个只读命令（ls, cat, git status, ...）
   含管道符/重定向/命令替换的命令不视为安全 → 继续检查
                           ↓
 Layer 2: 危险命令检测
   DANGEROUS_PATTERNS 包含 8 个正则：
   - rm -rf /（递归强制删除根目录）
   - mkfs.*（格式化文件系统）
   - dd if=...of=/dev/（直接写块设备）
   - chmod -R 777 /（危险的权限开放）
   - :(){ :|:& };（Fork 炸弹）
   - curl ...|(ba)sh / wget ...|(ba)sh（管道执行远程脚本）
   - > /dev/sd*（写磁盘设备）
   命中 → 直接 DENY
                           ↓
 Layer 2b: denyWrite 保护路径
   保护路径列表（默认）：
   - .mewcode/config.yaml
   - .mewcode/permissions.local.yaml
   - .mewcode/skills/
   仅对 WriteFile/EditFile 检查
   命中 → 直接 DENY
                           ↓
 Layer 3: 路径沙箱
   允许的路径范围：
   - 项目根目录及其子目录
   - /tmp 临时目录
   超出 → ASK（BYPASS 模式下跳过）
                           ↓
 Layer 4: 文件权限规则
   三级配置文件：
   ① ~/.mewcode/permissions.yaml      (用户级)
   ② {project}/.mewcode/permissions.yaml   (项目级)
   ③ {project}/.mewcode/permissions.local.yaml (本地级，gitignore)
   
   规则格式：Bash(git push) allow | deny | ask
   最后匹配的规则生效（高优先级覆盖低优先级）
                           ↓
 Layer 4b: Session 级规则
   allowAlwaysRules: 用户勾选 "Always allow" 后添加
   key = toolName:content  (如 "Bash:git push")
                           ↓
 Layer 4c: 沙箱模式
   如果 sandboxEnabled = true && 工具类别 = COMMAND
   → 拆分复合命令（按 && || ; | 切分）
   → 逐个检查是否有显式 deny/ask 规则
   → 无显式规则则放行（OS 沙箱已兜底）
                           ↓
 Layer 5: 权限模式矩阵
   mode.decide(tool.category()) → ALLOW / DENY / ASK
   - DEFAULT: FILE→ALLOW, COMMAND→ASK, UI→ALLOW
   - PLAN:   FILE→DENY,  COMMAND→DENY(除白名单)
   - BYPASS: 全部→ALLOW
   - ACCEPT: 全部→ALLOW
```

## 三、安全命令检测

```java
private boolean isSafeCommand(String command) {
    String trimmed = command.trim();
    // 包含任何 shell 元字符 → 不安全
    if (trimmed.contains("|") || trimmed.contains(";")
        || trimmed.contains("&&") || trimmed.contains(">")
        || trimmed.contains("$(") || trimmed.contains("`")) {
        return false;
    }
    // 精确匹配或前缀匹配白名单
    for (var safe : SAFE_COMMANDS) {
        if (trimmed.equals(safe) || trimmed.startsWith(safe + " ")) {
            return true;
        }
    }
    return false;
}
```

白名单包含 80+ 命令，例如：`ls, cat, grep, find, git status, git log, git diff, npm -v, go version, python --version` 等。

## 四、YAML 规则解析

```yaml
# ~/.mewcode/permissions.yaml
# - rule: "ToolName(pattern)"   effect: allow|deny|ask

- rule: "Bash(git push)"        effect: ask
- rule: "Bash(git *)"           effect: allow
- rule: "WriteFile(/etc/*)"     effect: deny
- rule: "ReadFile(*)"           effect: allow
```

解析器用正则 `^(\w+)\((.+)\)$` 拆分出 toolName 和 pattern。pattern 中的 `*` 被转换为正则 `.*`。

## 五、沙箱模式下的命令拆分

```java
if (sandboxEnabled && tool.category() == ToolCategory.COMMAND) {
    // 拆分复合命令，逐条检查
    String[] subcommands = content.split("\\s*(?:&&|\\|\\||[;|])\\s*");
    for (String sub : subcommands) {
        for (PermissionRule rule : fileRules) {
            if (rule.matches(toolName, sub)) {
                if (rule.effect == DENY) → 拒绝整个命令
                if (rule.effect == ASK)  → 标记需要询问
            }
        }
    }
    if (hasAsk) → ASK; else → ALLOW  // OS 沙箱已兜底
}
```
